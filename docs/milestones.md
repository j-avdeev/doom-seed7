# Task 2.5 — Connect framebuffer demo to real Seed7-generated WASM

## Status

**Task 2.5 should be started now.**

Task 1.5 successfully proved:

```text
Seed7 source → generated C → Emscripten → WebAssembly → JavaScript
```

Task 2.5 completes the final missing step:

```text
Seed7 source → generated C → Emscripten → WebAssembly → JavaScript → Canvas
```

## Goal

Make the existing browser Canvas demo use pixels generated by Seed7 code compiled through:

```text
Seed7 source → generated C → Emscripten → WebAssembly → JavaScript → Canvas
```

## Input

Existing files:

```text
src/platform/framebuffer_demo.s7
src/platform/wasm_probe.s7
web/index.html
web/main.js
web/styles.css
tools/build-wasm.sh
docs/browser-runtime.md
README.md
```

## Tasks

1. Preserve the existing JS/browser fallback demo.
2. Create or update the Seed7 framebuffer program so it exposes a stable callable interface.
3. Compile Seed7-generated C with Emscripten.
4. Export the required symbols from the WASM module.
5. Export required Emscripten runtime helpers, for example `ccall` or `cwrap`, only if needed.
6. Make `web/main.js` load the generated WASM module.
7. Make browser Canvas read framebuffer data from WASM memory.
8. Keep the old pure-JS visual fallback available if WASM loading fails.
9. Update `tools/build-wasm.sh`.
10. Update `README.md`.
11. Update `docs/browser-runtime.md`.

## Suggested exported interface

```text
doom_init(width, height)
doom_tick(frame_number)
doom_framebuffer_ptr()
doom_framebuffer_width()
doom_framebuffer_height()
doom_framebuffer_size()
```

If Seed7 cannot easily export these functions directly, create a thin C bridge around generated Seed7 C.

## Recommended implementation strategy

Current proof already demonstrates that generated WASM executes correctly.

The next step should be:

```text
1. Allocate a static framebuffer in generated code.
2. Fill framebuffer pixels from Seed7 logic.
3. Export framebuffer pointer and metadata.
4. Read framebuffer bytes from WASM memory in JavaScript.
5. Copy framebuffer into ImageData.
6. Render directly to Canvas.
```

If direct Seed7 exports are difficult:

```text
Seed7-generated C
        ↓
Small C bridge
        ↓
Emscripten exports
        ↓
JavaScript Canvas renderer
```

## Definition of done

* Browser opens `web/index.html`.
* WASM module loads successfully.
* Canvas displays pixels produced by Seed7-generated WASM.
* JS fallback still works.
* Exact build and run commands are documented.
* Any remaining Seed7/Emscripten limitations are documented.
